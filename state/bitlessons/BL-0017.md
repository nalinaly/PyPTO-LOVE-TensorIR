# BL-0017: An independent oracle must differ structurally

Changing scalar types while copying the production loop nest line-for-line is
not an independent correctness oracle. The first GDN Torch check duplicated
channel, head, value and key loops, so a shared state-layout or head-routing bug
could pass both implementations.

Use a different decomposition: vector reductions for conv/norm, explicit
`repeat_interleave` for grouped heads, and einsum/outer products for recurrent
prediction and updates. Keep only the sequential request/token order required
by causal state. Then measure numerical drift and set the smallest evidence
bound; do not choose a convenient tolerance before observing it.
