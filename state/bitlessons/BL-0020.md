# BL-0020: Profiling and timing are separate but must share state identity

Collecting kernel names/counts in a separate profiler run avoids perturbing
CUDA-event timing, but an opaque trace digest is not enough. Bind that profile
to the same typed problem, descriptors, dynamic lengths, reset/state kind,
graph mode and fixed device environment. Derive calls per invocation from total
calls and profiled invocation count.

For stateful attention/GDN, restore identical state before every warmup,
sample, inner iteration and profiled invocation outside the timed envelope.
Otherwise later iterations measure a different recurrence/cache state while
still appearing to share one benchmark key.
