# BL-0026: A wheel gate must test the installed product, not a target directory

`pip install --target site-packages` does not reproduce a virtual environment:
wheel `data/scripts` can land under `site-packages/bin` instead of the venv's
`bin`, so console-script tests fail for packaging reasons or silently remain
untested. Use pip's target-interpreter mode for a real install, prove module and
script ownership, then add shared test dependencies without exposing an
editable copy of the product.

Likewise, counting only the expected extension name does not prove a one-DSO
wheel. Enumerate every `.so`/`.so.*`, reject duplicate archive members, and
treat `ldd` failure or a forbidden/missing dependency as a hard failure on the
installed DSO.
