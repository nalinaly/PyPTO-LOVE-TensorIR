# BL-0033: Bound a decoder before schema validation allocates

A one-MiB serialized-input cap is insufficient if the parser allocates a
declared array or map before the application checks its schema. CompileRequest
initially inherited MessagePack's enormous default container/depth limits, so a
tiny allocation-bomb payload could OOM instead of raising `ValueError`.

Apply explicit parser limits for arrays, maps, strings, binary/ext fields and
depth before object construction, then enforce canonical schema and size again
after value construction. Test array32, map32 and deep-nesting bombs in both C++
and Python.
