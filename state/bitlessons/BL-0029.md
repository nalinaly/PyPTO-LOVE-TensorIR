# BL-0029: A paused child needs a living owner and recovery monitor

Sending verified `SIGSTOP` only to a workspace-owned process group prevents it
from allocating more memory, but exiting its parent runner loses exit status
and a reliable resume path. The first TargetInfo attempt exposed this evidence
gap: the group was stopped at 106/245, the runner exited, and the group was
absent before a later ownership-checked resume attempt; no resume signal was
sent. A later process-namespace reset means the disappearance cause is not
attributable from retained evidence.

Keep the runner alive while paused. Persist the pause in `process.json`, keep
checking memory, disk and protected NVIDIA compute, and send verified `SIGCONT`
only after recovery. Timeout leaves the owned group stopped for explicit
operator action. Never infer permission to signal an external PID from a
shared process name.
