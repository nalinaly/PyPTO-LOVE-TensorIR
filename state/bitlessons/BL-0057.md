# BL-0057: Cosmetic HIR names must not enter canonical compiler identity

## Risk

PyPTO marks function names and variable name hints as cosmetic in structural
identity. Interpolating those names into TensorIR symbols or SSA values would
give structurally equivalent HIR different source bytes, cache keys and Cubins.
It would also introduce escaping and locale-sensitive formatting hazards.

## Lesson

Canonical lowering must derive bytes only from semantic HIR. The first NVIDIA
emitter therefore uses compiler-owned names:

- `@pypto_vector_add`;
- `%arg0` and `%arg1`;
- `%result0`.

Function/global binding validity is still checked, but no HIR name is emitted.
Tensor dimensions are formatted with `std::to_chars`, not locale-sensitive
streams. Equivalent programs with different cosmetic names must produce
byte-identical TensorIR, while a real operand-order change remains visible in
the emitted operation.

This same rule applies to future pointwise/reduction/matmul lowering: generated
names use deterministic traversal order, never pointer values, process-unique
IDs, unordered-container iteration, spans, comments or ambient environment.
