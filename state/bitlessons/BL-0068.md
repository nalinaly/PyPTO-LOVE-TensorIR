# BL-0068: Resource-policy changes require a new evidence family

## Risk

A reviewed GPU transaction can be technically safe at lower host memory while
its frozen parent preflight, child gate and finalizer still require a higher
floor. Patching constants or translating the recorded value into the old
validator would make the evidence claim stronger than the code that actually
ran.

## Lesson

Treat admission policy as part of executable provenance. Preserve the accepted
family byte-for-byte and layer a new version that records the new exact floor
independently in both parent preflights, the direct child and the finalizer.
Reuse only hash-bound observation, isolation and numerical helpers, without
mutating their globals or spoofing process identity. Publish the new manifest
only after adversarial CPU tests and independent review.

An approximate operational judgment can therefore become an exact auditable
contract without rewriting history: here only protected correctness-smoke
admission moved to 22 GiB; exclusive admission, CPU coexistence, the owned-run
abort floor and GPU-free floor retained their prior values.
