# BL-0030: Test a transaction inside the same inherited lock envelope

Direct unit tests passed when no ambient environment-lock marker existed, but
the first full suite under `run_isolated.py` exposed 12 synthetic replacement
failures: fixture workspaces correctly rejected the real root workspace's
inherited shared-lock identity. The product was fail-closed; the test harness
had failed to model its execution envelope.

Synthetic transaction fixtures must remove and restore ambient lock markers,
then install exact fixture-specific markers only in inheritance tests. Always
run the final suite through the production isolation wrapper. That also proved
the intended law: shared consumers coexist, an exclusive replacement cannot
start through an arbitrary launcher, and a child inheriting the descriptor
keeps the flock after its parent closes its duplicate.
