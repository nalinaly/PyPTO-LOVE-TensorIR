# BL-0066: Correctness controls must contain their own failure modes

## Risk

An ignored bytecode cache can execute before a validator gets a chance to
reject it. Likewise, a suffix canary shorter than the largest possible masked
tail detects only part of an overrun; the remaining writes escape the backing
allocation and turn a correctness test into undefined behavior.

Pairwise numerical comparisons have a similar gap. If candidate and reference
sit on opposite sides of an independent oracle, each pair can satisfy a ULP
limit while candidate-to-oracle exceeds it.

## Lesson

Bootstrap reviewed Python dependencies by reading, hashing, compiling and
executing exact source bytes; reject matching pyc/cache entries before loading
any dependent control module. Test the validator itself with a valid poisoned
cache, not only malformed bytecode.

Size guard regions for the worst full-tile masking failure. For tile 16 and a
one-element tail, a 16-element guard safely contains all 15 excess writes and
lets the test reject them without out-of-bounds memory access.

For approximate math, bind candidate-to-framework-reference,
framework-reference-to-independent-CPU and candidate-to-independent-CPU
comparisons separately. Direct oracle comparison is mandatory; tolerance is
not transitive.
