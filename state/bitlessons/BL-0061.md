# BL-0061: GPU acceptance is owned by the finalizer, not the runner

## Risk

A numerically correct GPU child can still leave evidence that is too weak to
accept. If its finalizer permits extra nested claims, unknown replay files,
partial process/gate schemas or an untested publication path, a later report can
promote data that the isolated run never proved. A source-only AST test also
cannot catch a real binding mismatch such as addressing an `ArtifactTarget`
through a nonexistent member.

## Lesson

Treat the no-site CPU finalizer as an equal half of the correctness gate. It
must recursively reject broader claims, validate exact nested process,
preflight, gate, barrier, audit, target and replay schemas, enumerate the exact
replay directory, reopen the exact DSO without compiling or initializing CUDA,
and publish without replacement.

Before authorizing GPU execution, run both a complete synthetic finalization
transaction with mutation/no-replace coverage and a CUDA-hidden exact-DSO
compile/replay integration. Keep pre-execution replay files diagnostic until a
post-success provisional and the CPU finalizer join them.
