# BL-0052: A fixed GPU child is not fixed until startup imports and source shadows are fixed

## Failure

The first correctness-smoke controller locked its child argv and runner path,
but the controller/finalizer still started with site processing, the runner
bytes were initially self-anchored, and one diagnostic without `-B` generated
ignored Python caches plus a stale native DSO inside the PyPTO source package.

## Lesson

- `-S` blocks site processing but not `PYTHONPATH`; controller and finalizer
  need `-E -B -S`. The direct child/replay use `-I -B -S`.
- Hashing a runner from a mutable contract is not external provenance. Commit
  implementation first, then bind its commit/tree and every control blob in a
  separate manifest commit. Require a clean descendant root and no later
  control diff.
- Git-clean does not expose ignored import shadows. Explicitly reject ignored
  `.pyc`, native extensions and other files under the production package path.
- A preflight before `Popen` does not close the race. Hold the child behind a
  no-replace barrier, durably record ownership, re-audit, and let the child
  re-audit before importing the GPU framework.
- Replay evidence must be semantic. Reopen the exact compiler DSO and
  deserialize CompileRequest, BuildSpecs and Artifacts; self-reported file
  hashes alone are insufficient.

Generated diagnostic files should be moved to workspace quarantine with their
bytes intact, not deleted. A successful control test is still not a real GPU or
performance result.
