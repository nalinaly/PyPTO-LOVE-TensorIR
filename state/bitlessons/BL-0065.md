# BL-0065: Strict source provenance requires an external binary directory

## Risk

The private NVIDIA build guard rejects PyPTO tracked or untracked dirt
repository-wide and ignored files that overlap its strict build-input paths.
Each of the six compiler gitlinks separately rejects tracked, untracked, or
ignored files repository-wide. A nonignored CMake binary directory created
under the PyPTO worktree therefore becomes a provenance change.

Adding an in-tree binary directory to `.gitignore` or `.git/info/exclude` is
not an acceptable fix. The current PyPTO ignored-file query is scoped to strict
input paths and might not observe every top-level excluded directory; using
that gap would hide source-tree contamination and weaken auditability rather
than preserve the reviewed source closure.

## Lesson

For strict backend-ON builds, place the binary directory under the workspace's
ignored top-level `builds/` tree and point CMake `-S` at the exact clean
worktree. Build and test that product in place; never copy a DSO from another
checkout. Bind the CMake cache, generated revision flags, source worktree,
product path and exact DSO hash in evidence.

Retain a failed in-source attempt as diagnostic evidence when it demonstrates
the guard. Move it out atomically before rechecking source cleanliness; do not
delete it, add an exclusion, or weaken the provenance script.
