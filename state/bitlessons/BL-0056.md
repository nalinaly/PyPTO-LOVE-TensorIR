# BL-0056: A successful GPU child is not yet an accepted result

## Failure

The v3 child completed every launch and published a provisional result, but its
CPU finalizer failed on a control-side canonical-order defect. Treating the
child's zero exit as the milestone would have skipped exact control identity,
Artifact replay, serialized TargetInfo, run-sidecar and final-report checks.

## Lesson

Keep GPU execution and evidence promotion as separate transactions. A child may
record useful diagnostic facts, but acceptance requires the matching immutable
finalizer to join:

- root/control-manifest and exact source blobs;
- process, preflight, release gate and start barrier;
- CompileRequest, BuildSpecs, Artifacts and Cubin bytes;
- live runtime/TargetInfo and independent CPU semantic replay;
- execution, stream, synchronization, mutation and unload records;
- explicit scope and non-claims.

Never promote a provisional result with a finalizer from another control
version. Repair the generic validator, publish a new immutable manifest, rerun
the child, and finalize only the matching new provisional. This preserves both
the diagnostic history and the meaning of an accepted report.
