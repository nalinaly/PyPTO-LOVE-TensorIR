# BL-0043: A CACHE default is not a source revision lock

Changing an expected revision declared with `set(... CACHE ...)` left an old
value in an existing build tree. Build-info could therefore report the cached
claim while compiling another gitlink.

Use immutable source constants, query every dependency HEAD, reject tracked
dirt by default, and reserve any dirty-source override for explicit
development builds that can never become acceptance evidence.
