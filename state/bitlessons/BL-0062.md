# BL-0062: Unattributed GPU memory is an admission failure, not cleanup authority

## Risk

Under WSL, `nvidia-smi` can report nearly all device memory in use while listing
no Linux compute process or `/dev/nvidia*` handle. Treating the missing PID as
permission to reset the device, kill an unrelated process or restart the host
would violate isolation and can destroy external work.

## Lesson

GPU free-memory, compute-PID and protected-runtime-map checks are independent
admission predicates. If any predicate is red, leave external state untouched
and wait. Start only after a fresh parent preflight and child action-boundary
recheck are green, and audit again after the owned process exits.

For the frontend smoke, the device first showed about 23.9 GiB attributed to no
Linux process, so no launch or cleanup occurred. It later recovered naturally
to about 21 GiB free. The fixed controller then recorded empty external,
protected and unreadable sets before release, in the child, periodically and
after exit.
