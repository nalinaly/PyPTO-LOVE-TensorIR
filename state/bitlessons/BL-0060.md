# BL-0060: A one-producer facade must not expose producer injection

## Risk

Testing an exactly-once compiler transaction with a public or shipped producer
callback creates a second compiler route. A caller could return an ABI from one
source/request/options tuple and bind it to another final BuildSpec or Artifact,
while still appearing to satisfy an invocation-count test.

Linking the structured preparation layer into every low-level Artifact target
has a second cost: narrow producer/runtime tests acquire frontend symbols and
can fail or silently widen the compiler object boundary.

## Lesson

The public facade must hard-call the concrete private producer. Its only test
observation is a monotonic read-only invocation count. The producer result is a
private sealed move-only value that records exact source, request bytes and
validated compile-options identity before finalization. Artifact construction
recomputes those identities and consumes that same value exactly once.

Keep the low-level NVIDIA Artifact compiler translation unit independent of
frontend preparation. Put the public structured facade in the full compiler
source set, and test identity-rebinding rejection without shipping an alternate
producer function.
