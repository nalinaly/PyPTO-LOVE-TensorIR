# BL-0002: Split process state before splitting DSOs

Moving PyPTO compiler sources directly from `pypto_core` into a second shared
library would duplicate inline process-global state: variable unique-ID
counters, type singletons, and logger overrides. Hidden symbol visibility also
has no export/import contract yet.

The safe intermediate step is an internal object-library target embedded into
the existing single DSO. A real `libpypto_compiler` can be introduced only
after singleton definitions are out-of-line, the public C++ surface has export
annotations, and cross-DSO identity/logging tests pass.
