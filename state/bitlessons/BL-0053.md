# BL-0053: CUDA Tile host blocks are not physical worker warps

## Failure

A conventional-CUDA reading of Cubin `EIATTR_REQNTID=[128,1,1]` suggested that
an Artifact launch block hardcoded as `[1,1,1]` was the next definite bug. That
would have copied four physical worker warps into the host launch ABI.

## Lesson

CUDA Tile defines a different boundary: host grid dimensions select the Tile
Grid, but host block dimensions are unused and must be `[1,1,1]`. Worker-warp
count and `REQNTID` are compiler-selected physical implementation metadata;
their exact mapping must be treated as an inference unless the compiler
contract states it. They may be valuable for resource/profiling evidence, but are not
`CUlaunchConfig.blockDim*`.

When a new compiler IR changes the execution model, do not reinterpret low-level
metadata through ordinary CUDA kernel conventions. Reconcile all three layers
before changing an ABI:

- the compiler IR's documented host contract;
- its reference runtime and example launch;
- the emitted Cubin metadata.

Conflicting evidence must pause the patch. In this case the experimental
required-block propagation was fully reverted before commit, TensorIR remained
clean, and only the proven generic parameter-ABI defects recorded here and in
BL-0054 were repaired.
