# BL-0018: Optional framework baselines belong in child processes

A test-only Torch import at module collection time invalidated the operator
package's framework-free parent-process import proof even though production had
no dependency. Put optional framework baselines in explicit child processes,
hide every device API, create CPU tensors explicitly, and assert the parent did
not import the framework.

This keeps the standalone operator product decoupled while still providing an
independent numerical baseline. Test dependency availability may cause a
documented skip; it must never become an implicit wheel/runtime dependency.
