# BL-0048: A clean parent SHA does not prove clean compiled submodule bytes

`git status --ignore-submodules=dirty` can report a clean compiler parent while
headers or sources compiled from a submodule have tracked, untracked or ignored
changes. The parent gitlink binds only the committed submodule revision, not its
working-tree bytes. This applies to ordinary support dependencies as much as to
the headline backend: msgpack-c, libbacktrace and runtime ABI headers can change
Artifact or DSO behavior just as TensorIR, CUDA Tile or LLVM can.

For strict artifacts, enumerate the complete compiled direct-submodule closure.
At configure time and again as an always-run build dependency, require each
actual HEAD to equal the locked gitlink and reject tracked, staged, untracked
and ignored files. Include the closure policy in the pipeline identity, and
test every wrong revision plus representative dirty/untracked/ignored cases.

Generated ignored bytecode is still source drift for this boundary. Move exact
cache files to a recoverable backup and restart in a fresh build directory; do
not weaken the guard or silently clean unrelated files.
