# BL-0014: The ABI owner publishes; adapters verify identity

A framework adapter must not maintain a second abbreviated operator schema.
The operator project publishes one canonical manifest from its real types,
specs, constants, signatures and catalog; the adapter pins and independently
recomputes that digest, then re-derives the live bindings. Matching a package
version or merely finding attributes is not ABI evidence.

Packaging identity is a separate gate. Wheel RECORD ownership and PEP-660
`direct_url.json` need different proofs, and a normal editable install may
expose one dist-info plus its source egg-info. Accept only that exact logical
pair. Reject shadow paths, ambiguous metadata, links, and import-capable files
outside the pinned payload. Build frontends can also write caches or egg-info;
set workspace-local cache roots and audit every generated location.
