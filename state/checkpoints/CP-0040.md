# CP-0040: Standalone canonical schedule identity v1

- PyPTO `fa85e5a2c917af78ef94576073eb91c0891c4384`, tree
  `a39ddc2631b9717d288fefd74dd195864eb4e03c`, adds the versioned standalone
  `CanonicalSchedule` wire identity required before compiler-owned frontend
  Artifact preparation.
- Contract `pypto.canonical_schedule.v1` uses canonical MessagePack schema 1
  with lexically ordered top-level keys
  `canonical_schedule_schema_version`, `contract`, and `resolved_schedule`.
  Decode limits are fail-closed at 1 MiB, 7,191 objects, 7,190 aggregate
  items, map size 8, array size 128, string size 4,096, depth 4, and no BIN.
- The existing nested `KernelBuildSpec` schedule body is unchanged. The fixed
  986-byte empty build-spec fixture still hashes to
  `224db1389b70934afd871ba19ff4fa72bb2efce260602266a039e5c99c425345`,
  and the representative build-spec identity remains
  `93cab0033e5eb53ca87468c52348ffbfe5e17cd5d611080b2b8087af67fa93f6`.
- Public C++ and the single `pypto.compiler` Python surface expose immutable
  serialize/deserialize/identity operations. TensorIR remains private and no
  Torch, SGLang, CUDA context, compiler invocation, Artifact, or runtime handle
  is involved.
- Independent source review reported P0/P1/P2 = 0 and GO. Existing CP-0039
  backend-OFF and backend-ON build directories were reconfigured and rebuilt
  in place at exact head `fa85e5a`; they were not newly created for CP-0040.
  Both products pass the two native contract tests 2/2 and the combined Python
  canonical-schedule plus legacy build-spec suites 98/98. The enabled DSO
  embeds exact PyPTO revision `fa85e5a...`; the disabled DSO correctly reports
  `compiled=false` and has no private-backend revision.
- A first disabled-product Python harness run failed before pytest because the
  harness incorrectly required an embedded NVIDIA revision even when that
  backend was compiled out. The corrected exact-DSO invariant passed 98/98;
  this diagnostic is retained in EV-0053 and is not a product failure.
- CP-0040 accepts only versioned standalone schedule identity and preservation
  of the existing nested KernelBuildSpec bytes. It does not accept frontend
  specialization/ABI projection, strict Artifact preparation, TensorIR
  compilation, frontend GPU execution, operator-family codegen, frameworks,
  Qwen coverage, or performance.

## Resume action

Implement compiler-owned, data-only canonical projections for source IR,
static/symbolic specialization, argument/result/mutation ABI, and final callable
ABI. Then add a strict structured frontend compile facade that calls the real
producer exactly once and returns the final `KernelBuildSpec` plus `Artifact`
without exposing placeholder identities or internal `TensorIrModule`. Bind that
facade under `pypto.compiler`, and only then run HIR-authored vector add on the
real SM120 path.
