# CP-0005: Candidate/baseline execution isolation

- Framework launches now use explicit `pypto` or `baseline` profiles bound to
  separate project-local Python prefixes and identity locks.
- The baseline profile exposes only official pinned SGLang source and disables
  every general plugin; the PyPTO profile exposes the three project sources and
  verifies their installed entry points before a framework child can start.
- Environment identity covers Python ABI, complete distributions, Torch tree,
  CUDA/HIP runtime, SM120 and loaded DSOs. Effective sys.path, `.pth`, editable
  sources and meta-path finders are profile-audited.
- Protected process discovery includes `/proc/<pid>/cwd`. No zcode process was
  signalled. Parent interruption was verified only against an owned sleep
  process; the successful smoke recorded child `-15`, runner `143` and exited
  metadata.
- Frozen initial 0.8B/9B baseline launch scripts exist but have not run. The
  CPython 3.12 environment/lock and exact Triton wheel are still prerequisites.
- Candidate framework launch remains intentionally blocked by the inherited
  external editable Triton audit failure.
