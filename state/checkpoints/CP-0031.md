# CP-0031: Accepted strict TensorIR Cubin producer bridge

- PyPTO `f3bcaaccdfb169080628d56e461653b0ba3e0ad5` accepts exact
  canonical TensorIR source bytes together with immutable `CompileRequest` and
  `KernelBuildSpec`, verifies the source digest before compilation, and returns
  the already accepted immutable Artifact v1 through
  `Artifact.compile_strict(...)`.
- The public API remains standard-only and bytes-only. TensorIR/LLVM types stay
  behind a private no-EH/no-RTTI bridge; an exception-enabled coordinator maps
  the copied DTO into Artifact metadata and revalidates the complete producer,
  schedule, target, Cubin and callable ABI contract.
- The accepted structured route is exact SM120a, BF16/FP32-capable TensorIR to
  CUDA Tile bytecode 13.3.0 to pinned CUDA 13.3 `tileiras` Cubin. Ambient
  overrides, online candidate search, artifact fallback, foreign semantic
  routes and caller-supplied producer identities fail closed.
- TensorIR `1dcb38c20e53d07c97d3781cae538e33901bae30` carries the
  deterministic producer boundary. It executes a byte-verified private copy of
  `tileiras` with an exact sanitized toolkit environment, bounded diagnostics,
  timeout, data/RSS/file limits and private scratch monitoring.
- Linux child launch reserves descriptors above stderr before remapping closed
  host stdio, then uses fail-closed `close_range`. Scratch scanning is
  descriptor-relative with `openat`/`fstatat` and no symlink following;
  permission/I/O errors fail closed, only 100 consecutive live `ENOENT` polls
  are tolerated, and every post-exit scan error is rejected.
- Compilation is serialized in-process. After the first producer use, a forked
  child is rejected before acquiring inherited compiler state, avoiding a
  deadlock while keeping cache/runtime/process transport outside this schema.
- Pipeline specification
  `src/compiler/nvidia/structured_tensorir_explicit_v1.json` is bound by exact
  Git-blob identity `46610e0415598d010981e4bd07d0660c592401ac` across
  CMake, compiled build info, Artifact ABI, docs and tests.
- A never-before-used backend-ON build passes native CTest 8/8. Its exact
  product DSO runs the complete compiler suite with 132 passes and one expected
  backend-OFF-only skip. Static, dynamic and scalar TensorIR sources all
  produce and validate real SM120 Cubins through the pinned assembler.
- The accepted ON DSO SHA-256 is
  `3438f76a65f8021987b187e49ffaba25355a2f8e7920cf251b2c422fea50a134`.
  It has no RPATH/RUNPATH, only five standard runtime dependencies, and exports
  only `PYPTO_CORE_1` plus `PyInit_pypto_core@@PYPTO_CORE_1`; no private
  TensorIR/LLVM/MLIR/CUDA dynamic symbol leaks.
- A fresh backend-OFF build passes native CTest 6/6 and the exact DSO compiler
  suite with 128 passes and five expected skips. Its DSO SHA-256 is
  `b3524cb94e2c845e401dac6d5fac123472d66e8869cb00b4e5feb0e98643da3e`;
  it reports `compiled=false`, contains no private bridge source/dependency,
  and rejects strict compilation.
- The provenance gate passes on the exact clean PyPTO tree and all six compiled
  direct submodules: TensorIR, CUDA Tile, LLVM, msgpack-c, libbacktrace and
  runtime. It rejects every wrong revision plus tracked, untracked and ignored
  synthetic source changes. The root control regression passes 198 tests plus
  98 subtests beside the protected CPU-only lane without GPU compute or an
  external signal.
- TensorIR `1dcb38c...` and the PyPTO feature history are committed and pinned
  locally but are not published to their configured remotes. Fresh-clone or
  public reproducibility is not claimed until those commits are materialized.
- This checkpoint proves strict source-to-Cubin Artifact production only. It
  does not accept ArtifactCache publication, CUDA module/function/context
  loading, current-stream launch, workspace allocation, CUDA Graph capture,
  PyPTO frontend-HIR lowering, generic codegen, operators, TorchInductor,
  SGLang, Qwen correctness/coverage, profiling or performance.

## Resume action

Implement the compiler-owned persistent ArtifactCache as the next independent
transaction. It must key only by accepted Artifact projections, publish
atomically without replacement, revalidate bounded trusted-local bytes on
read, preserve exact producer/build provenance and contain no CUDA handle,
device query, context, stream, online autotuning or framework state. Only after
that cache gate may a separate process/device/CUcontext-bound
`NvidiaExecutable` loader/current-stream transaction begin.
