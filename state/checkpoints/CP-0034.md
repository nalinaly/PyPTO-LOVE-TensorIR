# CP-0034: Accepted parent NVIDIA runtime observation seam

- PyPTO `6361f110660a77f9a8dc542265575d8f7260b343` adds the
  framework-neutral parent observation required to construct a live
  `NvidiaTargetInfo` before `CompileRequest` creation. The public
  `NvidiaRuntimeObservation` is an immutable value containing the complete
  target, numeric Driver/Runtime API versions, an authenticated Runtime-library
  path and diagnostic context address/ID. It owns no CUDA handle.
- `observe_current_nvidia_runtime(driver_release, expected_runtime_path)`
  initializes only PyPTO's existing private Driver boundary, requires a regular
  non-null current context, queries UUID/PCI plus every TargetTraits resource,
  rejects prohibited/invalid compute modes and maps exactly BF16/FP32 plus the
  compiled TensorIR/CUDA Tile/toolkit identities.
- The Driver release string remains caller-supplied provenance. The numeric
  Driver API version is queried independently. The CUDA Runtime must already be
  globally loaded by the parent framework: PyPTO uses `dlsym(RTLD_DEFAULT)` for
  `cudaRuntimeGetVersion`, identifies the provider with `dladdr`, canonicalizes
  both provider and caller-audited expected paths as regular files and requires
  exact equality. It never opens a libcudart soname.
- The existing lock-free private-Driver PID latch is reused. A CPU fork test
  proves that after parent observation a child observation is rejected before
  touching an inherited mutex or Driver state. This does not detect arbitrary
  CUDA initialization performed by another library; fork children must use
  spawn/exec.
- CPU tests use distinct legal sentinels and compare all 21 TargetTraits fields,
  device identity, toolkit/TensorIR/CUDA Tile revisions, dtype set, Driver and
  Runtime API versions, provider path and context identity. Provider tests
  reject null functions, wrong canonical providers, Runtime status failures and
  non-positive versions. Public backend-OFF observation fails before CUDA
  loading.
