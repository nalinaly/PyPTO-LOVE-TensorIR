# CP-0042: Single-transaction structured compile facade v1

- PyPTO `642ff5bd79ee96b9e5a279a2bc945ad7a78362b7`, tree
  `77d8078d8df84dd7cf8544350918e25b8282976d`, adds the public immutable
  `StructuredCompileResult` and `CompileStructuredStrict` C++/Python facade on
  top of the CP-0041 structured preparation boundary.
- One call now performs one ordered transaction: prepare the HIR/request/
  schedule, hard-call the concrete private NVIDIA producer exactly once,
  normalize and seal its output, finalize the real callable ABI into the
  `KernelBuildSpec`, construct the `Artifact` from that same output, validate
  every joined identity, and return only after success.
- The producer result carrier is private, sealed and move-only. It binds the
  exact source digest, CompileRequest byte identity and producer-validated
  compile-options identity before Artifact construction. Artifact creation
  recomputes all three identities from the final request/spec and rejects
  source, request or options rebinding before provenance construction.
- No arbitrary producer callback, provisional Artifact, placeholder callable
  digest, cache lookup/publication or compile-twice discovery API is exposed.
  The only test observation surface is a monotonic read-only producer invocation
  counter. Existing `Artifact::CompileStrict` signature, wire identity and early
  process-claim behavior remain unchanged.
- `StructuredCompileResult` validates the CompileRequest byte-identity join,
  full BuildSpec digest, source, callable/kernel ABI, argument/result/mutation/
  static/symbolic projections and semantic route before it can be returned.
  Python exposes the same immutable `build_spec` and `artifact` pair from
  `pypto.compiler`.
- A diagnostic backend-ON build first exposed an unresolved-symbol cycle when
  the narrow Artifact test target inherited structured preparation. The final
  split keeps `nvidia_artifact_compiler.cpp` frontend-independent and places the
  facade only in the full compiler source list. The retained failed run is
  diagnostic, not acceptance evidence.
- Exact final-source backend-ON native tests pass 7/7 and exact-DSO Python tests
  pass 182 with 2 skips. Backend-OFF native tests pass 5/5, its narrow Python
  functional gate passes 7/7, and the full exact-DSO suite passes 175 with 9
  skips. The backend-ON DSO path retains a CP-0041-era directory label, but its
  embedded revision is explicitly asserted as `642ff5...` and its exact bytes
  are bound by EV-0055.
- Two independent final source reviews report GO and P0/P1/P2 = 0.
- CP-0042 accepts the public HIR-to-final-Artifact compiler transaction and its
  exact CPU/compiler validation. It does not accept CUDA module load or kernel
  execution through this frontend route, ArtifactCache publication, generic
  fused-loop coverage, structured matmul execution, any custom operator,
  framework registration, model coverage or performance.
