# CP-0033: Accepted CPU/fake-driver NvidiaExecutable v1 contract

- PyPTO `2842a1c5433cb3cfe9e4fbc7664ebe0ad8a4b129` adds a distinct
  internal NVIDIA runtime object boundary while preserving the single public
  `pypto_core` DSO. It consumes an immutable validated Artifact plus
  CompileRequest; construction is CUDA-free and KernelBuildSpec is no longer
  needed after its identity is bound into Artifact.
- `NvidiaExecutable` owns a once-only `Unloaded -> Prewarming -> Ready|Failed
  -> Unloading -> Unloaded` lifecycle. It binds creator PID, device ordinal,
  live regular CUcontext and stable context ID, latches prewarm/unload failure,
  rejects inherited objects after fork and makes explicit unload terminal.
- The backend-ON private Driver boundary opens only `libcuda.so.1` lazily,
  bootstraps `cuGetProcAddress_v2`, resolves typed CUDA 13.3 APIs with explicit
  legacy-stream semantics, then uses context-bound `cuModule*` loading. It
  never links libcuda/libcudart, retains a stream, uses TensorIR runtime, or
  exposes CUDA/TensorIR types.
- A lock-free PID latch permits a fresh child-created executable only when the
  parent never initialized the CUDA Driver. Inherited shared state uses a
  creator-PID custom deleter so a child does not touch parent mutex/CV/module
  state even during last-owner destruction.
- Prewarm verifies caller-observed CUDA Runtime API, Driver API, regular current
  context, parsed UUID/PCI identity, SM120 resources, exact Cubin entry,
  forced function load, flattened parameter widths, binary version, block/
  register/shared-memory/cluster legality and nonzero occupancy. Current green
  contexts fail before module load.
- `NvidiaLaunchPacket` performs all shape/stride/scalar packing and checked
  runtime-grid arithmetic before launch, allocates stable parameter slots and
  retains an execution lease. Successful Launch performs zero counted host
  allocations, revalidates process/context/device/stream context and rejects
  null, legacy-default, per-thread-default and green-context streams.
- `NvidiaCudaGraphLease` retains module lifetime for a future instantiated
  graph owner. It proves lifetime arbitration only; this checkpoint does not
  claim CUDA Graph capture/replay.
- Artifact v1 still carries no tensor dtype, device-address alignment/address
  space/access mode. Those remain typed operator/framework-adapter obligations.
  Its only accepted workspace remains static size zero/alignment one.
- Fresh backend-ON builds 1,902 edges and passes CTest 9/9. Its exact-product
  compiler plus public runtime Python gate is 142 passed/1 skipped. The ON DSO
  SHA-256 is
  `ef60b6a9749036eaff27786c5838b24fdd282b97b345315855c2994e2b3e4727`.
- Fresh backend-OFF builds 312 edges and passes CTest 7/7, including the
  direct fail-closed/fork stub test. Its exact Python gate is 134 passed/9

  `9ffd22915e5c2c694660f06f3db0455ee9df560e828fd6b8c13c8c3f478cee7a`.
- Both DSOs are RPATH/RUNPATH-free, have only five standard dependencies and
  the version/Python-init definitions, and have no CUDA, TensorIR or
  NvidiaExecutable dynamic symbols. Compile rows prove ON owns one driver
  source while OFF
  contains only the stub; both contain one runtime state and one binding row.
- Current seven-source provenance passes, every wrong revision is rejected,
  and representative tracked, untracked and ignored runtime/driver drift fails
  closed. Scoped Ruff/format and Pyright for the changed Python/stub surface,
  1,144 headers, 169 EN/ZH doc/nav pairs, 1,336 English-only checks and the

- Therefore CP-0033 accepts only the CPU/fake-driver executable contract and
  product isolation. It does not accept real libcuda resolution, Cubin module
  load, current-stream execution, numerical CUDA correctness, CUDA Graph,
  frontend lowering, operators, TorchInductor, SGLang, Qwen coverage or
  performance.

## Resume action

When a fresh exclusive `gpu-benchmark` preflight is green, run one exact-product
SM120 smoke in a PyTorch-owned context: compile/load static add, dynamic
non-aligned and scalar Cubins; prepare packets; launch on a real non-default
current stream; synchronize outside PyPTO; compare output; destroy packets and
graph leases; explicitly unload; then audit repeated module lifetime. Do not
bypass the gate or use stream handles 0/1/2. Only after that evidence closes
the real current-stream runtime gate should frontend-HIR lowering advance.
