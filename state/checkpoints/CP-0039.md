# CP-0039: Compile-free PyPTO HIR to TensorIR emitter v1

- PyPTO `07ab9ea1feb5f5cc5557c7b7c67e7ad33d15974e`, tree
  `c02d8ccd03b40193c5547cb9c4956c29a5ed92af`, adds the first real frontend
  lowering component after the accepted NvidiaExecutable runtime gate.
- The emitter is internal C++ in `src/codegen/nvidia/` and has no TensorIR,
  CUDA Tile, Torch, SGLang or other vendor header dependency. It does not invoke
  a compiler or device. It returns exact TensorIR source bytes plus immutable
  compiler-neutral input/result metadata.
- V1 accepts one well-formed Opaque function in the exact normalized form
  `SeqStmts[AssignStmt(tensor.add), ReturnStmt(result)]`: two distinct `In`
  tensor parameters and one returned tensor, identical positive static shapes,
  contiguous layout and FP32 or BF16 dtype. Broadcasting, dynamic/view/memref
  tensors, control flow, side effects, nested expressions and malformed identity
  relationships fail closed with bounded diagnostics.
- Canonical source uses only compiler-owned names: `@pypto_vector_add`, `%arg0`,
  `%arg1`, `%result0`. Cosmetic HIR names, pointer values, `UniqueId`, spans,
  comments, unordered iteration and ambient environment never enter source
  identity. Integers use locale-independent `std::to_chars`.
- Rank-one TensorIR omits explicit stride attributes and uses singleton result
  syntax; metadata still records logical dense stride `[1]` and
  `has_explicit_strides=false`. Rank two and higher emit explicit dense strides.
  Metadata order is exactly `Input0, Input1, Result0` and private construction
  prevents detached source/metadata fabrication.
- Exact FP32 `[128]`, FP32 `[2,3]` and BF16 `[7]` golden source hashes plus a
  broad structural/type/layout/identity/locale negative matrix are frozen in
  the unconditional native test.
- Clean backend-OFF configure/build/test runs `091116...89b3d0`,
  `091141...ac0540`, and `091343...5ef5a9` pass the emitter CTest 1/1. Clean
  backend-ON runs `091116...d963c3`, `091141...dfa80f`, and
  `091556...8ee40b` also pass 1/1. Both compile and link the emitter through the
  normal PyPTO compiler object boundary.
- CP-0039 accepts only compile-free HIR validation, deterministic TensorIR text
  emission, compiler-neutral static metadata and ON/OFF build integration. It
  does not accept TensorIR parsing, precompile callable ABI derivation,
  KernelBuildSpec, Artifact, Cubin, frontend runtime/GPU correctness, broader op
  families, framework/model coverage or performance.

## Resume action

Add a compiler-owned frontend preparation/compile API that consumes the
internal `TensorIrModule` and one explicit schedule, derives versioned
argument/result/mutation/static/symbolic identities, resolves the producer's
full callable ABI without publishing placeholder hashes, and returns the final
`KernelBuildSpec` plus strict `Artifact`. Then bind that API under the single
`pypto.compiler` Python surface and replace the handwritten TensorIR vector-add
compile case with `@pl.function`/HIR input. Do not route through the legacy
Ascend pass pipeline or expose TensorIR as a second product.
