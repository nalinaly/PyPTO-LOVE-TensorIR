# CP-0027: Accepted private TensorIR/CUDA Tile compiler composition

- PyPTO `5f755687...` now composes pinned TensorIR `233ab6ed...`, CUDA Tile
  `af241704...`, and LLVM `57109bef...` as private static compiler
  infrastructure inside the single public `pypto_core` DSO.
- The private configuration disables TensorIR Python, tests, tools and install,
  plus CUDA Tile C API, Python and CLI tools. Only the mandatory build-time
  `cuda-tile-tblgen` remains; no standalone TensorIR/CUDA Tile product target
  is present.
- TensorIR commits `f2270c6` and `233ab6e` make its public compiler target a
  correct embedding surface: MLIR/LLVM header requirements propagate to the
  parent, while header-only CUDA usage no longer injects an absolute toolkit
  RUNPATH into the product.
- The final 761,853,008-byte DSO SHA is `12b75a4e...c3def5`. It is the only
  product DSO, has no RPATH/RUNPATH, and has only the five standard runtime
  `DT_NEEDED` entries. `ICompiler::create` and the CUDA Tile compiler are
  present in that DSO.
- Exact-source bootstrap passes all 123 Python compiler tests in run
  `pypto-20260824T142538Z-247378-a1f074`. A device-hidden build-info probe
  proves `sm_120a`, the compiler factory, all three source revisions, CUDA
  13.3.73, and exact `tileiras` identity without creating a CUDA context.
- This checkpoint accepts composition and product ownership only. It does not
  accept HIR lowering, compiled kernel bytes, Artifact/cache/runtime, current
  stream launch, a private-backend wheel, any CUDA operator, framework route,
  model coverage, correctness, or performance.
